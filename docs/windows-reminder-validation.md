## 自动测试

`python/tests/test_reminder_matrix.py` 使用固定时间覆盖以下行为：

| 场景 | 结果 |
| --- | --- |
| 提前 24 小时 | 只返回 `1440` 分钟提醒，再次轮询为空 |
| 提前 2 小时 | 只返回 `120` 分钟提醒，再次轮询为空 |
| 到期 | 只返回 `0` 分钟提醒，再次轮询为空 |
| 应用重启 | 已发送记录保存在 SQLite，重启后不重复提醒 |
| 休眠跨过多个触发点 | 恢复后只发送最近一档，并把更早档位记为已处理 |
| 修改截止时间 | 清空旧发送记录，新截止时间可重新触发提醒 |
| 提前完成 | 已完成待办不提醒 |
| 关闭单项提醒 | `reminder_enabled=false` 的待办不提醒 |

休眠恢复逻辑原先会把错过的 24 小时、2 小时和到期提醒同时返回，导致同一待办连续弹出三条通知。现在只返回最近已到达的一档，正常持续运行时三档仍会分别触发。

## Windows 人工验证

| 场景 | 结果 |
| --- | --- |
| 到期系统通知 | Rust 轮询到虚构到期待办后，Windows 正常显示一条通知 |
| 真实睡眠和唤醒 | 待办在睡眠期间到期；唤醒后 60 秒内只出现一条通知 |
| 通知权限拒绝 | 临时将轻务通知设为关闭后，应用和 sidecar 正常运行且系统不显示通知；测试后已恢复原设置 |
| 开机启动关闭 | 状态按 `false → true → false` 验证，最终保持关闭 |
| 关闭窗口 | 主窗口隐藏到托盘，提醒进程继续运行 |
| 完全退出 | 菜单文案为“完全退出（停止提醒）”；点击后 Rust 主进程和 sidecar 均结束 |
